## 一、 项目来龙去脉：我们之前经历了什么？

本项目在进入当前 Git 仓库前，经历了三个关键演进阶段：

### 1. 第一阶段：世界观奠基与双线并行探索
- **世界观与数值总纲确立**（见 [GAME_MECHANICS.md](./GAME_MECHANICS.md)）：
  - 确定以 **公元 1050 年（宋仁宗皇祐二年）** 为唯一历史切面，融合《太阁立志传》的沙盘养成与《金庸群侠传 / 天龙八部》的武侠江湖。
  - 确定 **“确定性数值量化骨架 + LLM 动态叙事血肉”** 双层架构：将角色属性严格切分为**不进战中公式的天赋三维（根骨/悟性/颜值）**、**直接驱动战棋结算的实战四维（气血/身法/内力/抗性）**、以及**十艺百工（骑术/医术/毒术/琴艺/棋艺/书道/丹青/经义/策论/诗词）**。
  - 撰写出 **216 门武学全典**（[MARTIAL_ARTS_COMPENDIUM.md](./MARTIAL_ARTS_COMPENDIUM.md)，分天/地/良/凡四阶，含少林七十二绝技、逍遥北冥、大理六脉、慕容斗转、道藏九阴等）与 **38 处疆域重镇及 123 座特殊建筑设定**（[REGIONAL_MAPS_AND_BUILDINGS.md](./REGIONAL_MAPS_AND_BUILDINGS.md)）。
- **分支 A（宏观舆图与空间全景主线）**：
  - 绘制了涵盖北宋、大辽、西夏、吐蕃、大理及流求、琼州、高丽、交趾、日本真实海岸线的《华夏山海全景舆图》（`src/data/worldBaseSvg.ts` + `worldGraph.json`），支持按里程 $D$、地形系数 $T$、坐骑速度与轻功/骑术修正计算真实行军天数。
  - 逐张生成了 **38 处州府/名山/雄关的北宋青绿工笔 2.5D 等轴全景图** 与 **58 座核心特殊建筑的半 3D 内景图**，手工校准了点击多边形热点（`poly`）与牌匾锚点坐标。
- **分支 B（1,000 名历史与武林人物主线）**：
  - 编纂了 **1,000 名独立人物全录**（[CHARACTER_COMPENDIUM.md](./CHARACTER_COMPENDIUM.md)，含 `NPC-0001..0100` 共 100 位考据级公元 1050 年在世历史名臣巨匠，以及 `NPC-0101..1000` 共 900 位涵盖绝世大宗师至市井趟子手的武林群像）。
  - 按故宫南薰殿帝后名臣像、《宋史》记载与宋代服制考据，逐张独立生成了首批约 50+ 位核心历史名人与宗师的 `1:1` 头像与 `3:4` 全身立绘，以及 12 套门派/行当通用全身模板。

### 2. 第二阶段：痛点诊断与防跑偏共识
在多分支并行后，我们复盘发现了三大阻塞“可玩性”的痛点（详见 [ROADMAP_AND_TODO.md](./ROADMAP_AND_TODO.md)）：
1. **单文件原型体积触顶**：早期单文件 HTML 内嵌 Base64 图片膨胀至 20MB+，无法继续承载战棋引擎与千人状态机。
2. **跨分支命名分叉**：人物文档中存在 `东京汴梁`、`西京洛阳` 等 658 处旧地名写法，与地图分支统一的“宋辽夏 19 城三字府名（`开封府`、`洛阳府` 等）”尚未打通。
3. **资产铺量超前于玩法闭环**：美术与设定已完成 75%+，但核心创角、学武配招、8×8 战棋对决尚未实装。

因此确立了**两条最高优先级研发铁律**：
- **铁律一（暂停散装生图，主支线解耦）**：用宋式《营造法式》SVG 矢量内院（`SvgBuildingInteriorFallback.tsx`）兜底剩余 65 座建筑内景，用 12 套门派模板 + 宋风古籍名牌兜底未画立绘的 NPC，把补图放入非阻塞 Backlog，全力攻克代码可玩性。
- **铁律二（先骨骼跑通，后上 LLM）**：M0（工程合流）→ M1（创角·武学数值·养成经济）→ M2（8×8 战棋）→ M3（千人社交与风云榜）先做成不依赖大模型也能从头玩到尾的扎实单机 RPG，M4 再接入 LLM 三大引擎，M5 做双终局收官。

## 二、 关键技术细节与历史踩坑备忘（避坑指南）

1. **Zustand Store 与存档序列化同步**：
   - 全局状态集中在 `src/store/useGameStore.ts`，持久化结构定义在 `src/types/game.ts` 的 `SerializableGameState`，读写逻辑在 `src/utils/saveManager.ts`。
   - **进入 M1 新增主角三维（根骨/悟性/颜值）、已学武学列表、装备栏、背包物品、门派身份时**：务必在 `saveManager.ts` 中为旧版 M0 存档提供向后兼容的默认值填充（Fallback Defaults），保证玩家旧存档不会白屏崩溃。
2. **三层地图坐标与热点交互机制**：
   - 第一层 `WorldMapCanvas.tsx`：基于 `worldBaseSvg.ts` 与 `worldGraph.json`，支持平移缩放、悬停检视、Dijkstra 最短耗时寻路与按日骑马推进动画。
   - 第二层 `RegionMapCanvas.tsx`（`viewMode === 'region'`）：加载 `1376×768`（或 `isoViewBox` 指定尺寸）的地区全景底图，叠加 SVG 多边形可点击区域（`poly`）与古风竖排牌匾。
   - 第三层建筑内景（`viewMode === 'building'`）：在 `RegionMapCanvas.tsx` 内部判断 `interior.mode`——若为 `'image'` 则渲染 `public/assets/buildings/*.jpg` 及室内交互点 `spots`；若为 `'svg_fallback'` 则交由 `SvgBuildingInteriorFallback.tsx` 按区域主题色与建筑类别程序化渲染宋式庭院与热点。
3. **离线单文件预览构建（`npm run build:artifact`）**：
   - `scripts/build_preview_artifact.py` 会将 Vite 构建产物内联为无 Blob URL 的 IIFE 单文件 HTML（规避严格沙盒 CSP 限制）。平时本地开发只需直接用 `npm run dev`（`http://localhost:5173`），速度最快且支持 HMR 热更新。
4. **美术严禁造假原则（用户明确要求）**：
   - 用户在早期会话中明确强调：**绝不允许用 Python PIL / Canvas 几何绘图脚本伪造地图或人物画作，也不允许把同一张人物立绘复制改名冒充两个不同 NPC ID**。未来若启动 Backlog 补图，必须严格按 `.agents/skills/panorama-artist` 和 `.agents/skills/portrait-artist` 逐张独立生图并人工/视觉核验。
